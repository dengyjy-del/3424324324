# 🧬 LOOKSCORE

Телеграм-бот, который «оценивает» внешность по 10 параметрам лицевой эстетики
и выдаёт компактный отчёт с общим баллом, тиром и разбором зон роста.

Имя бота задаётся одной строкой `BRAND_NAME` в `.env` и подставляется во все
сообщения — переименовать можно за 10 секунд.

Есть обязательная подписка на канал и скрытый режим съёмки контента.

---

## Как это работает под капотом

Оценки **генерируются алгоритмически** — фото не анализируется нейросетью и
вообще не скачивается ботом. Логика в `rating.py`:

- **Коридор.** В обычном режиме общий балл всегда в диапазоне **5.0–7.4**,
  центр 6.15. Проверено на 20 000 прогонов: 100% попаданий.
- **Живые параметры.** Отдельные параметры расходятся вокруг общего балла
  (3.6–9.3), поэтому отчёт не выглядит плоским: где-то 8.3, где-то 4.1, а
  среднее держится в коридоре. Это и делает результат правдоподобным.
- **Детерминизм.** Seed = `sha256(соль + профиль + user_id + file_unique_id)`.
  Одно фото — один результат навсегда. Перезаливать ради лучшего балла
  бесполезно.

## Мини-апп

Telegram Mini App на том же процессе, что и бот: `python bot.py` поднимает
и polling, и веб-сервер. Кнопка запуска появляется в меню бота и под отчётом.

**Экраны:** Скан (загрузка фото → анимация с калиперной сеткой → кольцо с
оценкой и детализация), Профиль (статистика + график динамики с
переключателем дни/недели/месяцы), Гайды (7 разборов).

**Дизайн:** глассморфизм в духе iOS — тёмная база, три амбиентные авры за
матовым стеклом (`backdrop-filter: blur(28px) saturate(180%)`), крупная
табличная цифирь, пружинные переходы. Фирменный момент — раскрытие оценки:
кольцо с градиентом обходит круг, пока цифра докручивается до результата.
Именно этот кадр и уходит в ролики.

### Настройка

```env
WEBAPP_URL=https://your-domain.com   # пусто = мини-апп выключен
WEBAPP_PORT=8080
MIN_AGE=16
```

Telegram принимает **только HTTPS** с валидным сертификатом. Локально —
через `cloudflared tunnel` или `ngrok`, в продакшене — nginx с Let's Encrypt
проксирует на `WEBAPP_PORT`. Адрес нужно продублировать в @BotFather:
`/newapp` или `/setmenubutton`.

### Авторизация

Вход только через Telegram. Приложение открывается внутри мессенджера, где
пользователь уже аутентифицирован: Telegram передаёт подписанный `initData`,
сервер проверяет HMAC-подпись токеном бота и получает доказанный `user_id`.

Почты, паролей и своей базы сессий нет намеренно:

- **Конверсия.** Вход в один тап против формы регистрации — на таком трафике
  разница в разы. Каждое лишнее поле срезает часть аудитории.
- **Безопасность.** Нет паролей — нечего утекать, нечего брутфорсить, не нужны
  сброс пароля и подтверждение почты.
- **Данные.** Собирать email у аудитории 16–23 — это обязанности по GDPR
  (хранение, удаление по запросу, уведомление об утечке) без единого плюса
  для продукта: писать людям всё равно можно прямо в Telegram.

Подпись проверяется на каждом запросе, `initData` живёт сутки. Сравнение
подписи — постоянного времени, подмена `user_id` в строке ломает HMAC.

### Возрастной порог

`MIN_AGE=16` — порог согласия на обработку данных по GDPR по умолчанию.
Возраст спрашивается один раз при первом входе и хранится числом.

Порог меняется одной строкой в `.env`, но прежде чем опускать его, стоит
взвесить: в большинстве стран ЕС обработка данных пользователей младше 16
требует согласия родителей, а магазины приложений при возрастном рейтинге
12+/16+ проверяют именно такие механики. Экран отказа написан так, чтобы
не звучать как отказ в услуге, и предлагает то, что в этом возрасте
действительно работает.

## 📢 Обязательная подписка на канал

Пока человек не подписан, бот не отдаёт оценку: показывает экран с двумя
кнопками — «Подписаться на канал» и «Я подписался».

**Настройка:**

1. Добавь бота **администратором** в свой канал. Без прав админа Telegram не
   даёт проверить членство — это ограничение API, обойти нельзя.
2. В `.env`:

```env
CHANNEL_ID=@your_channel        # публичный канал
CHANNEL_TITLE=Looksmax Analysis # как назвать канал в тексте
```

Для приватного канала нужен числовой ID и ссылка-приглашение:

```env
CHANNEL_ID=-1001234567890
CHANNEL_URL=https://t.me/+AbCdEfGh
```

Пустой `CHANNEL_ID` = гейт выключен, бот работает для всех.

**Детали реализации:**

- Мимо гейта проходят `/help`, `/about`, `/myid`, `/demo_off`, кнопка проверки
  и код режима съёмки — чтобы ты не заблокировал сам себя.
- Положительный результат кешируется на 10 минут, отрицательный — нет. Поэтому
  кнопка «Я подписался» срабатывает мгновенно после подписки.
- Если бот не админ в канале — гейт **пропускает всех** и один раз пишет ошибку
  в лог. Так бот не выглядит сломанным при кривом конфиге, а ты видишь причину.
- ID из `ADMIN_IDS` проходят гейт всегда.

## 🎬 Режим съёмки (скрытый)

Для записи роликов. Отправляешь боту в чат кодовую фразу из `DEMO_CODE` —
включается режим, в котором:

- оценки в диапазоне **2.0–3.5**;
- строка `отчёт #57113A · @username` **скрыта** — в кадр не попадает ни номер,
  ни твой юзернейм;
- под карточкой остаётся одна кнопка «Подробный разбор», лишние убраны;
- сообщение с самим кодом **удаляется из чата** сразу, чтобы не светилось на
  записи экрана;
- результаты **не идут** в статистику и топ-10, база остаётся чистой.

Режим работает только для тебя и только в твоём чате. Выключение — `/demo_off`.

```env
DEMO_CODE=5526hfgsksuner12o900000fkmksjhfnijnnbnneduhna
DEMO_TTL_MINUTES=30
ADMIN_IDS=
```

**Два предохранителя — рекомендую не отключать:**

1. **`ADMIN_IDS` — заполни обязательно.** Пока поле пустое, код работает у
   любого, кто его узнает. А узнать его несложно: код попадает в историю чата,
   его видно на записи экрана до момента удаления, и он лежит в исходниках.
   Отправь боту `/myid`, впиши полученное число — и код станет бесполезен для
   всех остальных. При старте бот пишет в лог предупреждение, если поле пустое.

2. **Автовыключение через `DEMO_TTL_MINUTES` минут.** Страховка от главной
   ошибки: снял ролик, забыл выключить, а бот дальше выдаёт реальным
   подписчикам двойки. Обычный пользователь, получивший 2.4/10, скорее всего
   просто уйдёт из бота и никогда не вернётся — именно поэтому в основном
   режиме нижняя граница стоит на 5.0.

## Кастомизация

**Сдвинуть диапазоны** — `rating.py`, объекты `NORMAL` и `DEMO`:

```python
NORMAL = ScoreProfile(
    key="normal",
    overall_min=5.0, overall_max=7.4,   # границы общего балла
    overall_center=6.15, overall_sigma=0.55,
    param_min=3.6, param_max=9.3,       # границы отдельных параметров
    param_spread=1.15,                  # насколько параметры расходятся
)
```

**Добавить/изменить параметр** — кортеж `PARAMETERS` там же: эмодзи, название и
3 совета. Количество параметров можно менять свободно, остальное подстроится.

**Изменить тиры** — кортеж `TIERS` (порог, эмодзи, код, название, комментарий).

**Переписать тексты и вёрстку** — всё в `texts.py`.

**Переименовать бота** — `BRAND_NAME` в `.env`. Больше нигде править не нужно.

**Сбросить все оценки** — поменяй `SCORE_SALT` в `.env`.

**Скорость анимации** — `SCAN_DELAY` (по умолчанию 0.75 сек × 6 кадров ≈ 4.5 сек).

## Приватность

Заложено намеренно:

- **Фото не скачиваются и не хранятся.** Боту нужен только `file_unique_id`.
  Дешевле по трафику и чище юридически.
- **Юзернеймы не хранятся.** Публичного рейтинга в боте нет, поэтому в базе
  остались только Telegram ID и числа. Никакого списка пользователей, который
  можно слить или спарсить, у бота не существует.
- **Дисклеймер** про развлекательный формат стоит в `/start`, `/about` и в
  подробном разборе. Аудитория воспринимает такие цифры всерьёз, и часть
  пользователей — подростки.
- **Советы** в разборе — про сон, SPF, осанку, стрижку и поход к врачу при
  реальных вопросах. Без диет и «костоломства».

## Деплой на Vercel

Vercel — serverless: постоянного процесса нет. Поэтому в этом режиме бот
работает не на polling, а на **вебхуке**, а данные лежат в **Postgres**
(файловая система функции эфемерна, SQLite там теряется при холодном старте).
Код один и тот же — режим выбирается переменными окружения.

### 1. Postgres

Vercel → проект → **Storage** → **Create Database** → **Neon**. После
создания строка подключения сама появится в переменных как `DATABASE_URL`.

Можно взять и сторонний: neon.tech или supabase.com, free-тарифа хватает.
Тогда копируешь строку вида `postgresql://user:pass@host/db` руками.
Бери **pooled**-строку (с `-pooler` в хосте) — serverless открывает много
коротких соединений, и прямое подключение упрётся в лимит.

Таблицы создаются сами при первом запросе.

### 2. GitHub

В репозиторий кладётся **весь проект целиком** — и бот, и приложение:

```
api/index.py      ← точка входа Vercel
vercel.json
requirements.txt
public/           ← index.html и статика, Vercel раздаёт через CDN
webapp/           ← бэкенд приложения
bot.py  config.py  rating.py  texts.py  handlers.py
keyboards.py  middlewares.py  access.py  database.py
```

Папка `public/` обязательна: из неё Vercel отдаёт интерфейс напрямую с CDN,
не поднимая функцию.

**Файлы должны лежать в корне репозитория, а не во вложенной папке.** Если на
GitHub видно одну папку, внутри которой всё остальное, — Vercel не найдёт ни
`vercel.json`, ни `api/`. Проверить проще всего по прямой ссылке:
`github.com/<логин>/<репозиторий>/blob/main/api/index.py` — файл должен
открыться.

`vercel.json` намеренно содержит только `rewrites`. Блок `functions` добавлять
не нужно: Vercel сам распознаёт `api/*.py` как Python-функцию по наличию
`requirements.txt` в корне, а лишний блок ломает сборку с ошибкой
«doesn't match any Serverless Functions».

`.env` в репозиторий не попадает — он в `.gitignore`. Все секреты живут в
переменных Vercel.

### 3. Переменные в Vercel

Settings → **Environment Variables**. Для всех сред (Production, Preview,
Development):

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | токен основного бота от @BotFather |
| `BOT_TOKENS` | токены зеркал через запятую (пусто = зеркал нет) |
| `DATABASE_URL` | строка Postgres (Neon подставит сам) |
| `WEBHOOK_SECRET` | любая длинная случайная строка |
| `SETUP_KEY` | другая длинная случайная строка |
| `BRAND_NAME` | `LOOKSCORE` |
| `MIN_AGE` | `16` |
| `CHANNEL_ID` | `@твой_канал` (пусто = гейт выключен) |
| `CHANNEL_TITLE` | название канала для текста |
| `DEMO_CODE` | код режима съёмки |
| `ADMIN_IDS` | твой Telegram ID |
| `SCORE_SALT` | любая строка |

`WEBAPP_URL` задавать не нужно: если он пуст, адрес берётся из `VERCEL_URL`
автоматически. Задай его вручную, только когда прикрутишь свой домен.

Случайные строки удобно взять так:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

### 4. Импорт и деплой

Vercel → **Add New** → **Project** → выбрать репозиторий → **Deploy**.
Framework Preset оставить **Other**, `vercel.json` уже всё описывает.

### 5. Один раз после деплоя

Открыть в браузере:

```
https://<твой-домен>.vercel.app/api/setup?key=<SETUP_KEY>
```

Это регистрирует вебхуки, кнопку меню и список команд — сразу основному боту
и всем зеркалам. В ответ придёт JSON со списком ботов и их адресами. Дальше —
`/start` боту в Telegram.

**Повторять после смены домена** (например, при подключении своего) и после
**каждого добавления зеркала** — вебхук привязан к адресу.

### 6. Зеркала

Одному деплою можно подключить сколько угодно ботов: они делят базу, мини-апп,
XP, лимиты и рефералы. Токены — в переменную `BOT_TOKENS` через запятую, затем
Redeploy и `/api/setup?key=…`.

Проверка состояния всех ботов разом:

```
https://<твой-домен>.vercel.app/api/bots?key=<SETUP_KEY>
```

Подробная инструкция со скриншотом ответов и разбором ошибок — в
[MIRRORS.md](MIRRORS.md).

### Диагностика

`/api/health` показывает, отвечает ли база, сколько ботов подхватилось и как
настроен проект:

```json
{"ok": true, "database": "postgres", "database_connected": true,
 "bots_total": 16, "mirrors": 15}
```

Если ботов меньше, чем вписано токенов — смотри поле `skipped_vars`: там имена
переменных, значения которых не похожи на токен.

`/api/bots?key=<SETUP_KEY>` — состояние каждого бота: адрес вебхука, зависшие
апдейты, последняя ошибка Telegram.

Если `ok: false` — в поле `database_error` будет причина. Логин и пароль из
строки подключения там замаскированы.

### Строка подключения Neon

Neon по кнопке «Copy snippet» отдаёт строку с параметром
`channel_binding=require`. Драйвер `asyncpg` его не понимает и отправляет в
Postgres как настройку сервера — соединение падает. Код вырезает такие
параметры автоматически, так что строку можно вставлять как есть.

Единственное, что важно выбрать руками, — **pooled**-строку (с `-pooler` в
имени хоста). Прямое подключение упрётся в лимит соединений: serverless
открывает их много и коротко.

### Если вместо приложения открылась ошибка

Функция не падает молча: при проблеме с конфигом она отдаёт страницу с
причиной и списком переменных (задана / не задана, без значений). Открой
корень домена или `/api/health` — там та же информация в JSON.

Частые причины:

| На странице | Что делать |
|---|---|
| `Не задан BOT_TOKEN` | добавить переменную и **передеплоить** |
| Зеркало не отвечает | открыть `/api/setup?key=…` после передеплоя |
| `Token is invalid!` | токен скопирован с пробелом или обрезан |
| `CHANNEL_ID задан числом…` | добавить `CHANNEL_URL` или указать `@username` |
| `Не найден public/index.html` | папка `public/` не попала в репозиторий |
| `Не задана переменная DATABASE_URL` | не создана база: Storage → Neon |
| `База данных недоступна` | проверь строку подключения, открой `/api/health` |

Переменные Vercel подхватывает **только при сборке**: после любой правки
нужен новый деплой (Deployments → ⋯ → Redeploy).

### Что важно знать про этот режим

- **Лимит тела запроса 4.5 МБ.** Телефон снимает 8–12 МБ, поэтому приложение
  ужимает снимок в браузере до ~300 КБ перед отправкой. Заодно отчёт приходит
  заметно быстрее на мобильном интернете.
- **Вебхук всегда отвечает 200**, даже если обработчик упал. Любой другой код
  Telegram считает недоставкой и шлёт апдейт повторно — на serverless это
  цикл из повторов и дубли сообщений у пользователя.
- **Режим съёмки и дедуп альбомов переехали в базу.** В памяти их держать
  нельзя: каждый вызов функции может попасть на другой инстанс.
- **Антифлуд остаётся в памяти** и работает мягче обычного — на разных
  инстансах счётчики свои. Для защиты от спама этого достаточно.
- **Холодный старт** — первый запрос после простоя идёт 1–3 секунды.

## Деплой на VPS

```ini
# /etc/systemd/system/looksmax.service
[Unit]
Description=Looksmax Bot
After=network.target

[Service]
WorkingDirectory=/opt/looksmax_bot
ExecStart=/opt/looksmax_bot/.venv/bin/python bot.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now looksmax
```

Здесь работает polling, и `python bot.py` поднимает бота и приложение одним
процессом. SQLite подходит до нескольких тысяч пользователей в день; дальше
достаточно прописать `DATABASE_URL` на Postgres — код не меняется.
