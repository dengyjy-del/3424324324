# Зеркала: как подключить 15–20 ботов

Все зеркала работают как основной бот: одна база, один мини-апп, общие XP,
лимиты, серии и рефералы. Пользователь может писать любому из них — данные
у него одни и те же.

Проект на Vercel остаётся **один**. Дублировать деплой не нужно.

---

## Шаг 1. Создать ботов в @BotFather

Для каждого зеркала: `/newbot` → имя → username → в ответ приходит токен вида

```
7712345678:AAF3xkP-Qz9lmNo0PqRsTuVwXyZ1234567
```

Скопируй все токены в блокнот — они понадобятся целиком, вместе с числом
до двоеточия.

> Права администратора канала зеркалам **не нужны**. Подписку проверяет
> основной бот — так задумано, иначе пришлось бы добавлять 20 ботов в канал.

## Шаг 2. Вставить токены в Vercel

Открой: **проект → Settings → Environment Variables → Add New**

| Поле | Значение |
|---|---|
| Key | `BOT_TOKENS` |
| Value | токены зеркал через запятую, в одну строку |
| Environments | отметить **Production**, **Preview**, **Development** |

Пример значения (перенос строки не нужен, пробелы допустимы):

```
7712345678:AAF3xkP-Qz9lmNo0PqRsTuVwXyZ1234567,7798765432:AAHbcD-Ef1ghIjKlMnOpQrStUvWx7654321,7755512345:AAJmnO-Pq2rsTuVwXyZaBcDeFgHi1112223
```

`BOT_TOKEN` (основной бот) не трогай — он остаётся как есть.

**Альтернатива**, если 20 токенов в одной строке неудобно редактировать:
заведи отдельные переменные `BOT_TOKEN_2`, `BOT_TOKEN_3`, … `BOT_TOKEN_50` —
по одному токену в каждой. Оба способа можно совмещать; порядок значения не
имеет, дубли отбрасываются автоматически.

## Шаг 3. Передеплоить

**Deployments → последний деплой → ⋯ → Redeploy.**

Vercel читает переменные только во время сборки. Без передеплоя новые
токены не подхватятся — это причина №1, почему «вставил и не работает».

## Шаг 4. Выдать вебхуки

Открой в браузере один раз:

```
https://<твой-домен>.vercel.app/api/setup?key=<SETUP_KEY>
```

Настроит разом всех: основного и все зеркала. Ответ покажет каждого бота
отдельно:

```json
{
  "ok": true,
  "bots_total": 16,
  "bots_ok": 16,
  "bots": [
    { "id": "7712345678", "bot": "@looksmax_bot", "ok": true,
      "webhook": "https://твой-домен.vercel.app/api/telegram/7712345678" }
  ]
}
```

Если какой-то бот не настроился, у него будет `"ok": false` и поле `error`.
Исправь токен, передеплой и повтори — можно точечно по одному боту:

```
/api/setup?key=<SETUP_KEY>&only=7712345678
```

## Шаг 5. Проверить

```
https://<твой-домен>.vercel.app/api/bots?key=<SETUP_KEY>
```

Показывает по каждому боту: имя, адрес вебхука, совпадает ли он с ожидаемым,
сколько апдейтов зависло, последняя ошибка от Telegram. Сюда смотреть в
первую очередь, если зеркало молчит.

Затем открой любое зеркало в Telegram и отправь `/start`.

---

## Добавить ещё одно зеркало потом

1. Токен от @BotFather.
2. Дописать его в конец `BOT_TOKENS` через запятую.
3. Redeploy.
4. Открыть `/api/setup?key=…`.

## Убрать зеркало

1. Удалить токен из переменной, передеплоить.
2. Снять вебхук у самого бота, иначе Telegram продолжит стучаться:
   `https://api.telegram.org/bot<ТОКЕН>/deleteWebhook`
   (без этого шага ничего не сломается — сервер такие апдейты игнорирует, —
   но в логах будут предупреждения).

## Что происходит под капотом

Telegram не сообщает в апдейте, какому боту тот адресован — понять это можно
только по адресу, на который он пришёл. Поэтому каждому боту выдаётся свой
адрес вебхука:

```
/api/telegram/<числовой id бота>     ← id, это часть токена до двоеточия
```

Дальше апдейт попадает в общий диспетчер, и хендлеры отвечают от имени того
бота, которому пришло сообщение (`message.bot`). Отдельный процесс, отдельная
база и отдельный деплой на каждое зеркало не нужны.

Мини-апп у всех один. Telegram подписывает `initData` ключом, производным от
токена бота, через которого приложение открыли, поэтому сервер сверяет подпись
со всеми токенами сразу. Кнопка «поделиться» внутри приложения подставляет имя
того бота, через которого пришёл человек, — приглашения из зеркала не уводят
на основного.

## Частые ошибки

| Симптом | Причина |
|---|---|
| Зеркало молчит на `/start` | Не открыт `/api/setup` после передеплоя |
| В `/api/bots` бот не появился | Токен не прошёл проверку формата — смотри `skipped_vars` в ответе `/api/health` |
| `Unauthorized` у зеркала | Токен перевыпущен или бот удалён в @BotFather |
| Мини-апп: «подпись не совпала» | Токен этого бота не добавлен в переменные |
| Работало, после Redeploy отвалилось | Переменная отмечена не для всех окружений (нужны Production + Preview + Development) |
| Всё отвалилось разом | Локально запущен `python bot.py` — polling снимает вебхуки. Останови процесс и открой `/api/setup` |

## Лимиты

Telegram считает лимиты на каждого бота отдельно, так что 20 зеркал их не
исчерпывают. Общее у них — база Postgres и функции Vercel: на бесплатном
тарифе смотри квоту на количество вызовов, если аудитория вырастет.

Суточный лимит сканов (`DAILY_SCAN_LIMIT`) считается по пользователю, а не по
боту: перейти в другое зеркало и получить лишние попытки не выйдет.
