# Раздел «Оценки»

Всё в одном боте. Деплой на Vercel как обычно, через GitHub.

## Установка

**1.** `requirements.txt` — добавился `Pillow>=10.0`. Vercel поставит сам.

**2.** В переменные окружения Vercel (Settings → Environment Variables)
можно добавить, но не обязательно — у всего есть значения по умолчанию:

```
RATE_ADMIN_ONLY=1        # 1 — раздел виден только ADMIN_IDS, 0 — всем
RATE_TERMS_URL=          # ссылки в дисклеймере
RATE_PRIVACY_URL=
RATE_SUPPORT=@ascendlab_help
RATE_CONSENT_VERSION=2026-07-16
```

`BOT_TOKEN`, `ADMIN_IDS`, `DATABASE_URL` уже есть и переиспользуются.

**3.** Задеплоить. Всё.

## Локальный запуск

Тот же самый бот, тот же код:

```
python bot.py
```

или в PyCharm: правый клик по `bot.py` → Run.

Отдельного сервиса нет и не нужно. Одно «но» — оно было и раньше,
`bot.py` про него предупреждает: локальный запуск работает на polling,
а Telegram разрешает либо polling, либо вебхук. Пока крутится локальная
копия, версия на Vercel молчит. Вернуть: остановить процесс и открыть
`<адрес>/api/setup?key=<SETUP_KEY>`.

| Файл | Правка |

Новое: `mograte/`, `public/static/rate.v1.{js,css}`, `seed_photos/`.

Раздел садится на **уже открытое** соединение основного бота
(`rate_db.attach(db)`), своего пула не создаёт — на serverless второй пул
означал бы лишние соединения к Neon.

Фото лежат в базе (таблица `rate_photos`), не на диске: на Vercel
файловая система только для чтения.

API раздела — `/api/faces/*`. Префикс такой, потому что `/api/rate`
у вас уже занят под оценку скана.

## Как работает

**Онбординг.** Дисклеймер один раз, с версией: поднял
`RATE_CONSENT_VERSION` — спросят заново у всех. Дальше имя, возраст
(18+, жёстко), фото.

**Оценка.** Пять кнопок: sub 3 / sub 5 / LTN / MTN / Chad. Тир не
показывается, пока оценок меньше пяти.

**Повторов нет.** Пара «зритель — анкета» пишется в `rate_seen`
с первичным ключом. Повтор невозможен физически — ни у живых анкет,
ни у демо, оценил человек, пропустил или пожаловался.

**Демо-анкеты** подмешиваются, когда живых меньше `RATE_MIN_LIVE_POOL`.
Папка `seed_photos/`, см. README там же.

## Модерация

Кнопка «Пожаловаться» → карточка вам в личку с фото и снимком анкеты
на момент жалобы.

| Кнопка | Что делает |
|---|---|
| Удалить анкету | Фото стирается, показы прекращаются, владелец уведомлён |
| Скрыть на 24ч | **Сама не вернётся** — нужно новое фото |
| Отклонить | Остаётся в показе |
| Забанить | Доступ к разделу закрыт |

Жалоба на несовершеннолетнего прячет анкету сразу, не дожидаясь порога
в три жалобы.

Команды: `/rate_stats`, `/rate_reports`, `/rate_seed_reload`,
`/rate_unhide <id>`.

## Режим съёмки

Включается вашим обычным `DEMO_CODE`, дальше `/demo_card`:
фото → ник → оценка → карточка **«Алиса оценил(а) тебя на Chad»**
с кнопками «Оценить» и «Написать».

Кнопки — реквизит, в базу ничего не пишут. Каждая карточка пишется
в `rate_demo_log`, счётчик в `/rate_stats`.

## Выдача попыток

```
/tries 123456789 5    — по ID
/tries @nickname 5    — по юзернейму
/tries @nickname      — 5 по умолчанию
/tries @nickname 0    — сколько уже начислено
/whois @nickname      — знаю ли я такой ник
```

Начисление идёт в таблицу `purchases` с ценой 0 — туда же, куда
попадают попытки за XP. Основной бот уже умеет их считать через
`count_purchases("scan:<дата>:")`, так что его логику лимитов трогать
не пришлось. Складывается с `/gift`, сгорает в полночь UTC,
XP не списывается.

**Про юзернеймы.** Telegram не даёт ботам искать людей по @нику —
такого метода в Bot API нет. Ник запоминается, когда человек пишет
боту. Накопление началось с этой версии; для остальных — числовой ID.

**Снять начисленное командой нельзя**: записи общие с честно
купленными за XP, удаление задело бы и их. Сгорают сами.

## Если фото не грузится

Откройте в браузере:

```
https://ваш-адрес/api/faces/diag
```

Подписи не требует, открывается прямо со смартфона. Что смотреть:

| Поле | Плохой ответ | Что делать |
|---|---|---|
| `pillow` | `НЕ УСТАНОВЛЕН` | Vercel не поставил Pillow — проверьте requirements.txt и передеплойте |
| `python_multipart` | `НЕ УСТАНОВЛЕН` | не страшно: загрузка идёт в обход него |
| `stats` | ошибка вместо чисел | база не отвечает, смотрите `/api/health` |

Если страница вообще не открылась — раздел не подключился, причина
будет в `/api/health`.

В самом приложении при неудачной загрузке под полем появляется кнопка
**«Показать подробности»** — она выводит тот же отчёт прямо на экран.

## Если что-то не так

`/api/health` — их штатная проверка, показывает причину.

`/api/faces/diag` — версия Pillow, наличие python-multipart,
поддержка HEIC, объём фото, статистика раздела.
